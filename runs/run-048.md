## Root cause of exit 101 + fix

Every bot thread builds its own bevy App via `ClientBuilder::new_without_plugins()
.add_plugins(azalea::DefaultPlugins)`. azalea-client's default `log` feature adds
`bevy_log::LogPlugin`, and `LogPlugin::build` installs the **global** `log` logger
and `tracing` subscriber. With one App per bot thread, only the first App can win:
on older bevy_log this panics ("a logger was already initialized", `set_boxed_logger`
expect) → process exit 101; on bevy_log 0.19.1 it doesn't panic but errors per bot
(`Could not set global logger and tracing subscriber as they are already set`) and
every bot fails before joining (repro: `/tmp/bench-evidence/repro-botphase.log`,
9 errors, 0/10 bots).

Fix (azalea-documented pattern, no silencing):
1. `neutron-bot::init_logging()` — `OnceLock`-guarded, RUST_LOG-aware
   `tracing_subscriber::fmt().try_init()`; called from `run_bot_thread`.
2. Per-bot App: `azalea::DefaultPlugins.build().disable::<bevy_log::LogPlugin>()`.

## Secondary finding (fixed): bots never connected

With the logger fix in place bots still reported 0/10: the join-storm per-bot
timeout was 10s, but vanilla 26.2's config phase (registries/tags) takes ~26–28s
when 10 bots join concurrently, so every bot was killed mid-config before the
`Spawn` event. Raised join-storm/distributed/spread timeouts to 90s
(`a77dc86`). After the fix: `Join storm: 10/10 bots connected, p50=26041ms`.
