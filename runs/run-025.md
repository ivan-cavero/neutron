## 1. Causa raíz (vanilla 26.2 javap)

`WorldgenRandom` extiende `LegacyRandomSource` e implementa `BitRandomSource`. Solo overridea `next(int)`:

```
next(bits) wrapping Xoroshiro = (int)(xoroshiro.nextLong() >>> (64-bits))
nextLong()   = next(32)<<32 + next(32)     // DOS nextLong de xoroshiro
nextDouble() = (next(26)<<27) + next(27)   // DOS nextLong de xoroshiro
nextFloat()  = next(24) * 2^-24            // ya correcto
nextInt(n)   = BitRandomSource (next(31))  // ya correcto
```

Neutron usaba un único `xoroshiro.nextLong()` para `next_long` y `next_f64`.  
`setDecorationSeed` llama `nextLong()` dos veces → **todas** las features (ores, sculk, árboles) nacían de un decoration seed distinto al de vanilla.

Evidencia: `tools/java-probe/src/ProbeWorldgenRandom.java` vs `server-26.2.jar`.

